# RELIASTRA — The Aperture

The identity for Reliastra: one mark, four segments, one observation point.

`preview/index.html` is the review — construction, lockups, true-size proofs,
surfaces, palette, application rules and the asset manifest. Serve it with:

```bash
node design/logo/serve.cjs        # http://localhost:4173
```

Every file in this directory is generated by `generate.cjs`. Nothing is
hand-edited afterwards.

---

## The mark

Four segments of equal width, assembled along the edges of a square rotated
45°, each segment running **past** the vertex it meets. One amber diamond in
the opening.

```
                ●  vertex (N)
               ╱ ╲
              ╱   ╲            segment  w 13u
             ╱     ╲           overrun  +7u per end
            ╱  ◆    ╲          core     22u diamond
           ╱   core  ╲
          ●           ●        rotated square
           ╲         ╱         80u point-to-point
            ╲       ╱
             ╲     ╱
              ╲   ╱
               ╲ ╱
                ●  vertex (S)
```

### Why this and not something else

**A frame with no front.** A square rotated 45° is a boundary — a field, an
aperture, a measurement plane. It has no top, no face and no direction, so it
sits beside a wordmark, inside a browser tab and on an evidence record without
ever reading as a mascot. An icon inside a rounded square is the single most
common tell of a generated product identity; a rotated square is the opposite
decision.

**Four equal parts, two of each.** Four segments answer to four equal
quadrants: two independent vantage points and two readings. The product's
method — observe, correlate, attribute — is in the geometry rather than in a
caption.

**The overrun is the mark.** Each segment passes its vertex and stops. That one
irregular move inside an otherwise exact figure is what separates this from a
diamond with a dot in it, and it is what keeps the mark legible at 16 px: the
diagonals stay open, so the figure never collapses into a solid lozenge.

**Amber is the reading.** The core is the signal square the interface already
uses for an observation point. Amber is the product's single accent **and** its
degraded state — the accent colour of this product is the colour of something
needing attention. That collision is deliberate and it is why the core is never
recoloured for decoration, and never switched off.

**Nothing decorative.** No gradient, no shadow, no rounded corner, no optical
correction. The mark is correct in one colour, at any size, on any surface —
which is the same standard the product holds its own evidence to.

## Construction

| Property | Value |
| --- | --- |
| Master grid | 100 × 100 |
| Rotated square | 10 → 90 on both axes (80 u point-to-point) |
| Segments | 4, equal, 13 u wide, mitre ends (no cap) |
| Segment overrun | +7 u past each vertex |
| Core | 22 u half-diagonal diamond, centred on (50, 50) |
| Clear space | one segment width (13 u) on every side |
| Minimum size | 16 px (favicon) |

Source of truth is `generate.cjs`; `construction.svg` and `parts.svg` are the
specification plates.

## Colour

| Token | Value | Role |
| --- | --- | --- |
| Observatory void | `#08090A` | Field on dark surfaces |
| Instrument light | `#F2F2EE` | The mark on dark surfaces |
| Signal amber | `#D9A441` | The core — an observation point |
| Product ink | `#0B1220` | The mark on paper |
| Brand blue | `#2563EB` | The core on paper |

Two-colour or one colour. On light surfaces the core becomes brand blue; it
never becomes amber, because amber is a state rather than a decoration.

## Lockups

The wordmark is RELIASTRA set in **Inter SemiBold**, letterspaced 0.21 em and
**outlined to vector paths** at generation time. The lockups therefore carry no
font dependency: they render identically in a README, an email client, a print
pipeline and a browser tab. Inter is the interface face, so the wordmark and
the product set in one voice. Gap between mark and name: 30 u against a 100 u
mark.

## Frontend integration

`generate.cjs` also writes the paths the site serves, so the identity cannot
drift from the code:

| Path | Contents |
| --- | --- |
| `frontend/public/logo.svg` | 32 px icon, declared in `app/layout.tsx` metadata |
| `frontend/public/logo-mark.svg`, `logo-mark-ink.svg` | Mark |
| `frontend/public/logo-lockup.svg`, `logo-lockup-ink.svg`, `logo-lockup-stacked.svg` | Lockups |
| `frontend/public/icon-192.png`, `icon-512.png`, `apple-touch-icon.png` | Icons |
| `frontend/public/social/reliastra-email-avatar.{svg,png}` | Avatar |

In the application the mark is `ApertureMark` and the lockup is `Wordmark`, both
in `frontend/src/components/site/wordmark.tsx` — the same figure, drawn with
`currentColor` so it is correct in any chrome.

## Regenerate

```bash
node design/logo/generate.cjs
```

Requires `@resvg/resvg-js` (raster export) and `opentype.js` (wordmark
outlining), resolved from `/home/user/.cache/tools/node_modules`. Set
`RELIASTRA_TOOLS` to point elsewhere. Inter SemiBold is read from
`@expo-google-fonts/inter`.
